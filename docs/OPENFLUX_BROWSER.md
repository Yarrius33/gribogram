# OpenFlux и GriboGram

Исследован публичный проект: https://github.com/p1neappleXpress/OpenFlux

Документация описывает цепочку «клиент → транспорт Яндекс Документов → выходной узел → интернет».
VPS может быть выходным узлом. Передача данных курсором не устраняет необходимость этого узла.

В исходном `transport/yandex/yandex.go` нативный клиент устанавливает Origin, Cookie и User-Agent для WebSocket. Браузерный WebSocket не позволяет произвольно устанавливать эти заголовки. Получение параметров документа также требует проверки междоменных запросов, сессии и captcha. Поэтому наличие VPS само по себе не подтверждает работоспособность чисто браузерного варианта.

Для реализации нужны:

1. Выбранный совместимый протокол клиента и выходного узла.
2. Подтверждённый браузерный доступ к документу и collaboration WebSocket либо отдельный нативный компонент/расширение.
3. Согласованная аутентификация узла, документ, адрес и доступ к VPS через защищённую конфигурацию среды.
4. Проверка под реальными сетевыми ограничениями: доступность Яндекса не гарантирует доступность всех используемых его адресов.
5. Переключатель режима: при отключении используется обычный транспорт Telegram. Отключение маршрутизации приложения не может отключить системный VPN пользователя.

Туннель не реализован и не развёрнут. Текущий переключатель в интерфейсе управляет обычными WebSocket-шлюзами, а не Яндекс Документами.
