## Порядок работы

1. Аудит текущих возможностей без дублирования существующих функций.
2. Прокси: WebSocket-менеджер, резервирование, импорт, восстановление соединения.
3. Чаты и сообщения; затем плеер, файлы и офлайн.
4. Оформление и клавиатура.
5. Автоматизация и внешние сервисы.
6. Брендинг и итоговая проверка.

## Ограничения

- Нативные MTProto/SOCKS5/HTTP CONNECT требуют серверного WebSocket-моста. Адреса этих протоколов нельзя выдавать за работающие WebSocket-прокси.
- Облачная синхронизация, AI, погода и внешние хранилища требуют выбора сервисов и авторизации. Автоматическая публикация переписки требует отдельного явного действия пользователя.
- Серверные ограничения Telegram (4 ГБ, сроки удаления, роли, Premium, время доставки) нельзя снять изменением браузерного интерфейса.
- Сохранение удалённых сообщений не восстанавливает незагруженную историю и требует отдельной политики локального хранения.
- Исходный репозиторий уже имеет ошибки TypeScript и отсутствующий tests/init.js; полный зелёный прогон до этих изменений недоступен.

## Уточнения пользователя

- Пропускать функции, требующие покупки серверов/собственной инфраструктуры.
- Исключение для обсуждения: VPS допустим как выходной узел OpenFlux. Покупка и развёртывание не выполнены; VPS, документ и доступ не предоставлены.
- Режим обхода должен отключаться. Для WebSocket-шлюзов переключатель уже реализован. Транспорт Яндекс Документов пока не реализован.
- ИИ должен быть локальным, без отправки текста внешнему провайдеру.

## Выполненные изменения — первая итерация

1. WebSocket-прокси: список до 20 шлюзов, приоритет, переключение на резерв при ошибке, строгая валидация, совместимость со старой настройкой одного адреса. Управление на обоих экранах входа и в «Данные и хранилище». Импорт HTTPS-списка с ограничением размера и времени, применение после Save. Переключатель отключает прокси. Обновления передаются между вкладками; до авторизации сохранение настроек перезагружает экран входа, чтобы перезапустить незавершённое подключение; события online и смены сети инициируют переподключение. HTTP fallback отключён при включённом прокси. Реальная связь через сторонний шлюз и отсутствие потерь сообщений НЕ проверены.
2. Выделение: Ctrl/Cmd переключает сообщение, Shift использует существующую диапазонную логику, двойное касание на сенсорных устройствах начинает выделение вместо быстрой реакции. Кнопки и ссылки сохраняют своё поведение. Альбомные интерактивные элементы требуют отдельной проверки.
3. Навигация: стрелки перемещают фокус между отрисованными строками списка чатов, Enter открывает строку. Ввод текста и существующие Alt+стрелки не перехватываются. Полная навигация через границы виртуализированного списка пока не реализована. Escape уже обрабатывается существующей навигацией приложения.
4. Плеер: точные 0.5×/1×/1.25×/1.5×/1.75×/2× для аудио и видео. Исправлено несоответствие подписей и фактических скоростей аудио.
5. Брендинг: GriboGram в заголовках/экранe входа/PWA, исходный red.svg — основная иконка, brown.svg сохранён как отдельный ресурс. Созданы PNG/ICO, обновлены favicon и значок непрочитанных. Дизайн исходных SVG сохранён.
6. Локальный ИИ: отдельный редактор в композере при наличии текста. Исправление текста и три тона через браузерный LanguageModel Prompt API. Без внешнего API и автоматической отправки результата. Применение только по кнопке и только если исходный черновик не изменился. Отмена, уничтожение модели и ограничение 8000 символов. Требуется поддерживаемый браузер/устройство; реальный инференс в этой среде НЕ проверен. Самостоятельная универсальная WebGPU-модель не добавлена (новые библиотеки запрещены AGENTS.md).
7. Исправлена конфигурация подмены MockClient в Webpack: учитываются реальные пути импортов и абсолютный путь замены. Полноценный mock-сценарий пока не подтверждён браузерной проверкой.

## Проверки

- Webpack: сборка с пустыми API-переменными компилируется; это не подтверждало запуск, так как исходная подмена MockClient не работала.
- Smoke-проверки транспорта: валидация, миграция настроек, дедупликация, ограничение списка, переключение резервов, отказ незавершённого handshake и штатное закрытие — пройдены на контролируемом WebSocket.
- Smoke-проверки локального ИИ: отсутствие API, формирование задачи, отмена, лимит текста и уничтожение модели после успеха/ошибки — пройдены с контролируемой моделью. Реальная модель недоступна.
- ESLint изменённых компонентов и логики: без ошибок. Полный webpack.config.ts содержит исходную ошибку длины комментария вне изменённых строк.
- Stylelint новых модулей: без ошибок, предупреждения о browser baseline для resize/user-select.
- TypeScript: те же 858 исходных диагностик; новых сочетаний файл/код ошибки нет. Порядок union-типов в текстах сообщений может меняться после генерации языковых типов.
- Скрипты npm run check:ts и check:css отсутствуют; использованы tsc, eslint и stylelint напрямую.
- Jest в исходном проекте не запускается из-за отсутствующего tests/init.js. Новые тестовые файлы не создавались согласно AGENTS.md.

Остальные пункты исходного списка остаются открытыми. Этот документ не означает, что вся дорожная карта уже реализована.

### Проверка обычного клиента с локальной API-конфигурацией

- Webpack development: успешная компиляция 5408 модулей.
- Chromium: экран входа с GriboGram загружается, менеджер прокси виден; неверный SOCKS5-адрес отклоняется, отключение сохраняется, ошибок страницы не обнаружено. На ширине 390 px горизонтального переполнения нет.
- API-значения находятся только в игнорируемом .env, не добавлены в Git и документацию.
- Вход в аккаунт, отправка сообщений, доступ к реальным прокси и inference локальной модели не проверены.

## Итерация: копирование, журнал, публичные каналы и секунды

Реализованы интерфейс копирования/скачивания обычного защищённого содержимого, пересылка-копия через выбор адресата, просмотр публичного канала без автоматической подписки и локальный журнал полученных удалений. По последнему уточнению пользователя приватный канал Telegram не создаётся. Время отправки сообщений дополнено секундами. Поведение, поддержанные типы и конкретные ограничения описаны в [CONTENT_AND_HISTORY.md](CONTENT_AND_HISTORY.md).
